# Make your portfolio yours

This is a blank starter, not a completed project, a belt or a credential. You decide what to include and where to keep it. The files need no package installation, AI account or server to edit.

## 1. Create your own copy

You need a GitHub account to create a GitHub repository. When this starter is available as a GitHub template, open that repository, choose **Use this template → Create a new repository**, choose an owner, name and visibility, and create it. GitHub's [template instructions](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template) show the current steps. A repository made from a template is a new repository you own; it is not the Developer Dojo publishing repository.

If you have the files without a template repository, you can instead create a repository you own and [upload the files](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository). Keep `index.html` and `README.md` at the top level, and preserve the `docs` folder and `LICENSE`. If your repository was created with a README, replace or edit that file rather than expecting two files with the same name.

## 2. Show evidence, not just claims

Edit `README.md` on GitHub or on your computer. Replace each prompt with your actual outcome, stack and agent roles, decisions, checks, failures and limitations, and credits. Delete any prompt that does not fit. Keep examples fictional or use work you have permission to share. Record what you actually verified, not a model's claim or a made-up benchmark.

The optional `index.html` is a separate, self-contained webpage. Edit its title, introduction and project card to match work you can share. The starter contains no completed project. It works without a build tool or JavaScript. To see changes locally, open your edited file in a browser; you can also edit the file directly in GitHub. Your Markdown and webpage do not update each other automatically.

For an independently reviewed or regulated deliverable, state who reviewed it and what remains unverified only when you have evidence and permission to share that information. An AI-produced artifact or this portfolio is not professional approval or a Dojo certificate.

## 3. Protect privacy and credit sources

Before making anything public, inspect the current files and any attached history for passwords, keys, client information, private URLs, personal data, images, spatial scans and material you cannot share. A private repository or a later deletion is not a substitute for checking what you upload. Review collaborators' consent and the licenses of third-party code, datasets, media and fonts.

The starter's own `LICENSE` describes the license for the template. It does not grant rights to your projects or third-party content. Choose terms for material you own or may license; GitHub explains [repository licensing](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository). Ask an appropriate adviser when rights are unclear.

## 4. Optional: publish the website

GitHub Pages availability depends on repository visibility and your plan. A Pages site may be public even if its source repository is private. Publishing is optional: the README can stand alone, and you can keep your own copy private when available.

After reviewing the files and committing them to your own repository:

1. In the repository, open **Settings → Pages**.
2. Under **Build and deployment**, choose **Deploy from a branch**, select the branch containing your files and its root folder, then save.
3. Wait for GitHub's deployment to complete. Open the URL shown in Pages settings and verify the title, evidence and links on a phone and computer.
4. If you update your work, commit the change and check the published page again. To stop publishing, use the Pages settings for your repository.

GitHub's [Pages guide](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) and [publishing-source guide](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) are authoritative if its interface or plan limits change. The Dojo does not create, host or verify your repository or page for you.
